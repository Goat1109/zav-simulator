# RC8 Offboard 경로 시험

ROS 시험 노드 → `/zav_real/offboard/request` → 기존 단일 MAVLink 브리지 → PX4.
브리지가 위치 유지 목표를 20Hz로 준비하며, 시험 노드는 경로 실행만 요청한다.
두 번째 UART, MAVROS, DDS Agent를 추가하지 않는다. 자동 무장·이륙·모드 전환 명령은 없다.
기존 EV 실패 감지·기압계 전환·LAND 대응이 우선한다.

## 2026-11-13 실기 로그에서 확인한 문제

- 사각형 중단 기록의 RC8은 1513µs였다. 기존 코드는 LOW(≤1300)/HIGH(≥1700) 외의 값을
  즉시 `pilot_mode_or_RC8_exit`로 처리했다. 물리 스위치 전환 중간값과 비동기 HEARTBEAT를
  고려하지 못한 구현이다. 당시 실제 FC 모드 기록이 없어 실제 모드 이탈 여부는 확정할 수 없다.
- 전진 중단 직전 목표 x≈1.123m, FC 위치 x≈0.141m로 목표 오차가 약 0.982m였다.
  기존 궤적은 기체 응답과 관계없이 시간만으로 진행하므로 곧 1m 중단 기준에 도달할 수 있었다.
  3m/s는 위치 목표 궤적의 속도이며 실제 기체가 그 속도로 이동했다는 뜻이 아니다.
  초기 기체 응답이 느렸던 물리적/FC 제어 원인은 이 발췌만으로 확인할 수 없다.
- 중단 뒤 표시되는 현재 오차는 발생 당시 오차가 아니다. 이제 최초 실패 시점의 FC 모드,
  RC8, 위치, 목표, 오차를 `fault`에 고정 기록하고 `state`에 별도로 표시한다.

## 변경 후 실행 순서

빌드된 새 코드 적용을 위한 브리지 재시작은 착륙·비무장 상태에서 한다.
이 문서의 명령은 운용 설명이며 이번 검증에서 실기체에 실행하지 않았다.

1. lio/livo/super_lio 중 하나를 실행한다. 모든 터미널의 ROS_DOMAIN_ID를 맞춘다.
2. 기존 단일 브리지와 모니터를 실행한다. 컨테이너의 현재 alias는 다음과 같다.

   ```bash
   # 터미널 B (이미 켜져 있으면 중복 실행하지 않는다)
   bridge
   # ros2 launch zav_real_control rc_flight.launch.py publish:=true offboard:=true

   # 터미널 C
   state
   ```

3. 조종자가 기존에 검증한 절차로 이륙해 실제 Position 모드에서 정지 호버링한다.
   RC8은 LOW로 둔다. 시험 노드는 아직 실행하지 않는다.
4. 무장·IN_AIR·정상 EV/FC 피드백·Position 정지 조건을 만족하면 브리지가 현재 위치/yaw
   목표를 준비한다. `state`의 `준비 완료 — RC8 전환 대기`를 확인한다(최소 1.2초 전송).
5. RC8을 HIGH로 전환한다. 실제 FC 모드가 Offboard인지 확인한다.
   브리지는 진입 위치·방향을 고정해 유지한다. 스위치의 중간 PWM은 중단 사유가 아니다.
6. `Offboard 호버링 준비 완료 — 시험 명령 입력 가능`을 확인하고 시험 명령 하나를 실행한다.

   ```bash
   # 터미널 D: 현재 사용자 alias에 execute:=true가 포함되어 있다.
   go_front
   # 또는 go_right / go_back / go_left / waypoint_square / waypoint_circle
   ```

   alias 없이 실행하려면:

   ```bash
   ros2 launch zav_real_control offboard_test.launch.py test:=go_front execute:=true
   ```

7. 명령 수락 시 현재 위치·기수·높이를 새 시험 기준으로 잡는다.
   먼저 3초간 위치 유지(정지 상태 최소 1초 확인), 이후 경로를 진행한다.
8. 완료 후 마지막 위치·방향을 계속 유지한다. 자동 착륙하지 않는다.
   다음 시험은 기존 시험 터미널을 Ctrl+C로 종료하고, 다시 호버링 준비 표시를 확인해
   새 명령을 실행한다. 정상 완료/취소마다 브리지를 재시작할 필요가 없다.
9. RC8 LOW 및 실제 Position 복귀로 조종권을 회수한다. 기존 경로는 취소되며 자동 재개하지 않는다.
   착륙은 조종자가 기존 절차대로 한다.

Position에서 미리 실행한 시험 명령은 **거절**하고 해당 실행 세션을 재사용하지 않는다.
Offboard 호버링 준비 후 그 시험 노드를 종료·재실행해야 한다. 스위치만 켠 뒤 지연 실행되지 않는다.
실제 FC 모드가 계속 Position이면 경로를 시작하지 않는다. RC8 HIGH 자체가 모드 전환 성공의 증거는 아니다.

## 여섯 경로

| 명령 | 경로 |
|---|---|
| `go_front` | 명령 수락 시 기수 기준 앞으로 5m |
| `go_right` | 같은 기준 오른쪽 5m, 기수 유지 |
| `go_back` | 같은 기준 뒤로 5m, 기수 유지 |
| `go_left` | 같은 기준 왼쪽 5m, 기수 유지 |
| `waypoint_square` | 앞 5m → 오른쪽 5m → 뒤 5m → 왼쪽 5m. 각 변 끝에서 정지·대기 후 시계 방향 90° 회전 |
| `waypoint_circle` | 반지름 2.5m 시계 방향 1바퀴. 초기 기수 유지, 원주 시작점 복귀 |

모든 경로는 명령 수락 시 높이를 유지한다. 사각형 좌표축은 시험 시작 때 고정되며 모서리에서
기수를 돌려도 다시 회전시키지 않는다. 마지막 모서리에서도 회전해 처음 기수로 복귀한다.
원 중심은 시작점의 오른쪽 2.5m이며 별도의 중심점 진입 구간은 없다.

## 제어와 제한

설정은 `config/offboard_tests.yaml`이다. `config:=/절대/경로.yaml`로 대체할 수 있다.

- MAVLink `LOCAL_NED`, `SET_POSITION_TARGET_LOCAL_NED`, type_mask=2552:
  위치 xyz와 yaw만 활성화한다. 속도·가속도·yaw-rate 필드는 IGNORE다.
- 기본 기준 속도 상한 3m/s, 가속도 3m/s², yaw 변화율 상한 60°/s.
  5차 보간의 명목 궤적 제한이며 실제 속도는 PX4 제어기와 기체 응답에 따른다.
  FC 파라미터를 바꾸지 않고, 실제 속도 3m/s 도달을 보장하지 않는다.
- `max_reference_lead_m=0.5`: 새 목표가 실제 위치보다 0.5m 넘게 앞서지 않도록
  궤적 시계 진행을 제한한다. 기체가 느리면 목표도 기다린다.
- `max_reference_yaw_lead_deg=20`: 제자리 회전에서도 목표 yaw가 실제보다 20° 넘게
  앞서지 않도록 기다린다. 추종 대기/재개 시 명목 가속도 곡선과 달라질 수 있다.
- `max_tracking_error_m=1.0`: 기존 목표와 현재 위치 오차가 1m를 넘으면 전송 중단을 고정한다.
  이 실패 기준을 완화해서 문제를 숨기지 않는다.
- `segment_timeout_s=90`: 명목 구간 시간+90초 이내 완료하지 못하면 중단한다.
  목표를 기다리는 시간도 이 벽시계 타임아웃에 포함한다.
- `acceptance_m=0.2`, `stopped_speed_m_s=0.15`, `yaw_acceptance_deg=5`, `settle_s=1`:
  위치·속도·방향 조건이 1초 유지돼야 도착으로 판정한다.
- `entry_hold_s=3`, `dwell_s=2`: 명령 시작 위치 유지와 각 도착/회전 후 정지 대기.
- 거리 최대 5m, 반지름 최대 2.5m, 기준 속도 최대 3m/s, 가속도 최대 5m/s²,
  기준 yaw 변화율 최대 60°/s. 위치 선행 제한은 실패 오차 한계보다 작아야 한다.

## 취소와 실패의 구분

- 시험 노드 요청이 0.3초 끊기면 경로를 취소하고, 정상 FC 피드백 기준 현재 위치·yaw로
  유지 목표를 새로 고정한다. 브리지 자체의 20Hz 전송은 계속한다.
  Ctrl+C가 기체를 즉시 정지시키거나 자동 착륙시키는 명령은 아니다.
- 완료한 시험 노드를 종료해도 마지막 목표를 유지한다. 같은 세션의 재수신으로 경로가 재개되지 않는다.
- RC8 LOW는 진행 중 경로를 취소한다. 실제 Position 복귀 전까지 위치 유지 목표를 보낸다.
  실제 FC 모드가 Land/Return/Altitude 등으로 바뀌면 Offboard 목표를 보내지 않는다.
- FC/EV 피드백 이상, 기존 EV handoff/jump, 로컬 위치 리셋·급변, 추종 오차/구간 시간 초과,
  setpoint 스케줄 0.25초 단절, 잘못된/중복 시험 요청은 전송을 중단하고 실패를 고정한다.
  실패 고정 후에는 착륙·비무장 상태에서 원인 확인 및 브리지 재시작이 필요하다.
- RC/ATTITUDE/LOCAL_POSITION/IN_AIR/ESTIMATOR_STATUS 피드백 허용 나이는 0.5초다.
- 사용자가 제공한 FC 값은 `COM_OF_LOSS_T=1.00s`, `COM_OBL_RC_ACT=Position Mode`다.
  브리지 전체 또는 목표 전송이 끊기면 FC의 Offboard-loss 설정에 따른다.
  이번 작업에서 FC 파라미터를 조회·변경하지 않았다.
- 기존 EV 이상에 의한 기압계 전환·LAND 로직은 별도로 우선한다.
  장애물 회피·충돌 방지·자동 이륙은 이 노드의 기능이 아니다.

## state 표시와 활성화 옵션

첫 줄의 실제 FC 모드를 우선 확인한다. Offboard 줄에는 위치 유지 준비/경로 진행 상태를,
별도 줄에는 시험 완료/취소/실패 및 명령 거절 이유를 표시한다. 진행률은 피드백에 따라
진행하는 기준 궤적 비율이다. 목표 선행 제한 중에는 `기체 추종을 기다리는 중`이 표시된다.
실패 발생 시점의 모드·RC8·오차는 현재 오차와 구분해 고정 표시한다.
`mode_history`에는 최근 실제 FC 모드 전환과 당시 RC8을 보관한다.

`offboard:=true`는 브리지의 위치 유지/경로 전송 기능을 활성화한다. 시험 노드가 없어도
정상 Position 호버링 중 준비 스트림과 Offboard 진입 후 유지 스트림을 보낸다.
`execute:=true`는 시험 노드가 경로를 요청하도록 한다. false는 미리보기다.
두 launch 기본값은 false를 유지하며, 현재 사용자 alias에는 true가 명시되어 있다.

## 검증 범위

실제 장치 대신 가짜 MAVLink 연결로 검증한다. 여섯 경로, 좌표·속도·yaw 제한,
노드 없는 준비/유지, 중간 RC8 PWM, 실제 모드 확인, 사전 명령 거절, 명령 취소/재실행,
느린/정지 기체의 목표 선행 제한, 실패 당시 오차 고정, 기존 EV LAND 우선 처리를 포함한다.
실제 비행·모터 구동 검증은 수행하지 않는다.

이번 수정 검증: 관련 회귀 테스트 103개 통과, 1개 skip. argo 컨테이너에서
`colcon build --packages-select zav_real_control --symlink-install` 성공. 실제 FC 연결/비행 명령 없음.
