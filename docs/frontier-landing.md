# Frontier 최상층 착륙 검증

실사 텍스처 지형의 기존 최종 XY `[-0.98290, 3.61785]`m에서 정상 착륙하도록
최상층 바닥의 충돌면 방향을 수정하고 작은 평탄 패드를 추가했다.
`./run_super_sim.sh frontier`가 사용하는 기본 지형에 반영되어 있다.
500.54m/203경유점 경로, 최종 목표 높이 24.18171m, `common.yaml`은 변경하지 않았다.

원래 바닥의 접지 영역은 아래를 향했다. 수정 전 최상층에서 바로 시작한 시험에서는
기체 body Z가 바닥보다 아래인 22.825~22.829m에 걸려 시동 후에도 이륙하지 못했다.
기존 전체 경로 시험에서도 착륙 접촉 뒤 비정상 회전 신호와 LIO 발산으로 착륙 판정에 실패했다.
반경 2m, Z 22.69~22.99m 범위의 아래를 향한 수평 충돌 삼각형 1,974개의 winding을 수정했다.
꼭짓점 위치와 삼각형 형상, 사진 텍스처는 그대로다. 이 수정만 적용한 단독 시험에서도
PX4의 착륙 감지와 자동 시동 해제를 확인했다.

추가 패드는 기존 바닥 위의 1m × 1m, 두께 2cm 정적 상자다.
상단 Z는 22.85871m로, 검사한 바닥 최고점보다 1cm 높게 맞췄다.
전체 층을 덮는 가상 바닥이나 높은 플랫폼을 만들지 않았다.
`frontier_visual/frontier_textured_flight.usda`의 `TopLandingPad`에 정의되어 있다.

Isaac과 RViz를 켜고 최상층에서 직접 이륙해 약 24.13m까지 상승한 뒤 3초 호버링하고
기존 `/zav/super/land` 서비스로 PX4 LAND를 요청했다. 패드 적용 후 동일 세션에서
두 번 연속 `landed=true`, `ARMING_STATE_STANDBY`, 제어기 `LANDED`를 확인했다.
두 번째 시험은 착륙 상태에서 다시 이륙한 반복 시험이다. 강제 시동 해제와 정답 위치 제어는 사용하지 않았다.

| 시험 | 결과 |
|---|---|
| trial01-baseline | 수정 전 바닥에서 기체가 걸려 이륙하지 못함. 진단 후 종료. |
| trial02-upward | 충돌면 방향 수정만 적용, 정상 착륙·자동 시동 해제. |
| trial03-pad | 패드 적용, 정상 착륙·자동 시동 해제. 최종 XY 오차 약 1.7cm. |
| trial04-pad-repeat | 같은 패드에서 재이륙·착륙 성공. 최종 XY 오차 약 7.8cm. |

기록과 원시 PX4 피드백은 `log/frontier-20261119/landing-fix/`에 있다.
`verification.json`이 종합 판정이며 각 시험의 `landing-audit.json`, `native.jsonl`에
상태 전환과 착륙 감지·시동 상태가 남아 있다.
이번 검증은 최상층 이착륙만 대상으로 하며 수정 후 전체 500m 경로를 재시험한 것은 아니다.

빠른 재시험에서는 `ZAV_SUPER_MISSION_FILE`에 최상층 시험 임무 JSON을 지정해
시뮬레이터를 시작했다. 내비게이션은 세션에 기록된 동일 임무를 자동으로 사용하며,
다른 임무를 명시하면 좌표 불일치를 막기 위해 실행을 거절한다.
이 환경 변수를 지정하지 않으면 기존 출발점과 전체 경로를 사용한다.
